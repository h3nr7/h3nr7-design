Rendering from satellite and elevation data

I tested several heightmap formats as the source for the terrain mesh, from 8-bit greyscale JPEGs to GeoTIFFs. JPEG is fast to load and decode in the browser, but it is a poor fit for elevation data:

  • Low precision — 8 bits gives only 256 height levels, so terrain ends up stepped.
  • Compression artefacts — lossy compression adds noise that shows up as bumps.
  • No absolute scale — each image is scaled to its own min and max.

Why GeoTIFF fixes it

It stores 16- or 32-bit elevation values along with georeferencing metadata, so every vertex has real coordinates and overlays line up.

Decoding on the server keeps the client light: the browser gets a ready-to-use grid of heights.

Building a miniature world

I then used the same pipeline to build a miniature 3D model of Mallorca from two inputs: a heightmap for displacement and a satellite image as the albedo texture.

  1. Subdivide a plane and displace each vertex by its sampled height.
  2. UV-map the satellite image onto the displaced mesh.
